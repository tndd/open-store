# テーブル定義
テーブルは種類によってはupdateを許してはならないという点に注意。
注文履歴の存在のため、内容を改竄することはできない。

## 商品: Item
作成された商品は、内容編集を行うことはできない。
内容に変更を加えたならば、別バージョンの商品として扱う。

**バージョン管理の仕組み:**
- `item_id`: 商品の概念的なID（商品そのものを識別）
- `id`: 商品の特定バージョンのID（価格や説明等の具体的な内容を持つ状態を識別）
- 同じ商品でも内容変更のたびに新しいレコードが作成され、異なる`id`を持つ
- 取引では必ず特定バージョンの`id`を参照することで、後から商品内容が変更されても取引時点の情報を保持

| name       | type   | 説明                               |
| ---------- | ------ | -------------------------------- |
| id         | uuid   | 商品バージョンの一意識別子（取引で参照される）          |
| item_id    | uuid   | 商品の概念的ID（全バージョン共通）               |
| user_id    | uuid   | 誰の商品かを表す                         |
| created_at | time   | このバージョンの作成日                      |
| name       | text   | 商品名                              |
| price      | int    | 価格                               |
| exp        | time   | 商品の消費期限                          |
| body       | text   | 説明文を含む文章                         |
| images     | text[] | 商品の画像ファイルへのパスのリスト。先頭をメイン画像として扱う。 |

## ユーザー: User
こっちはバージョン管理する必要はない。

**認証:**
認証にはAuth.js（NextAuth）のマジックリンク認証を使用するので、パスワードのカラムがない。

**権限:**
ユーザーには単なるエンドユーザーから販売者、そして管理者というroleが存在する。

| name       | type | 説明                                              |
| ---------- | ---- | ----------------------------------------------- |
| id         | uuid | ユーザーの識別子                                        |
| created_at | time | 作成日                                             |
| name       | text | 名前                                              |
| address_id | uuid | デフォルトとして指定する住所ID。初住所登録時にはAddressテーブルにも情報が追記される。 |
| email      | text | メールアドレス（認証用・一意制約）                               |
| role       | enum | 買い手・売り手・管理者の区別 （BUY,SELL,ADMIN）                 |

### 住所: Address
住所の詳細についてはUserテーブルからこちらに分離する。

User初作成時の挙動:
- デフォルト指定されたアドレスのnameは蛇足になるため読み込まれないようにする。初登録時に自動設定されるnameは空文字にする。
- 作成日はUser=Addressとなるようにしておく。

**Warn: User初作成時のuser.id循環参照問題**
- User.address_idとAddress.user_idの循環参照により、通常の順次作成では制約エラーが発生する。
- そのため、User作成時は必ずトランザクション内でUser-Addressを同時作成すること

| name        | type | 説明            |
| ----------- | ---- | ------------- |
| id          | uuid | アドレス識別子       |
| created_at  | time | 作成日           |
| user_id     | uuid | このアドレスの保有者識別子 |
| name        | text | 登録先住所につける名前   |
| phone       | text | 登録先住所の電話番号    |
| address     | text | 住所            |
| is_archived | bool | 無効化されたか       |

## 取引: Transaction
配送先の住所は後でトラブルにならないように、ここでも保存して冗長性を持たせる。
Address.idの内容を記録しておくことで、後出し変更のトラブルを追跡できるようになる。

キャンセルについて:
- 取引自体のキャンセルを行う場合は、このカラムもろとも関連すべてをcascadeで削除する
- だが原則として取引キャンセルは認めないものとしてシステムは運用すること

| name         | type | 説明                    |
| ------------ | ---- | --------------------- |
| id           | uuid | 取引の識別子                |
| timestamp    | time | 取引成立時刻                |
| buyer_id     | uuid | 買い手                   |
| seller_id    | uuid | 売り手                   |
| dest_addr_id | uuid | 配送先の住所識別子(Address.id) |

### 取引の要素: TransactElement
買い物かごの中のそれぞれの要素というイメージ。

キャンセルについて:
取引の中の部分的なキャンセルというのは確かに起こり得る。
基本的にキャンセルは注文から15分以内なら許可というところかな。

**重要:** `item_id`は`Item`テーブルの`id`（商品の特定バージョン）を参照します。
これにより取引時点での商品の価格・内容が確定的に保存されます。

| name        | type | 説明               |
| ----------- | ---- | ---------------- |
| id          | uuid | 取引セットにおける1取引の識別子 |
| transact_id | uuid | 取引セットの識別子        |
| item_id     | uuid | 対象商品の特定バージョンID（Item.idを参照） |
| quantity    | int  | 商品の数             |
| is_canceled | bool | キャンセルされたかどうか     |

# セキュリティ仕様
## ログイン認証
認証システムには、**Auth.js（NextAuth）+ マジックリンク認証**を使用する。

**技術仕様:**
- **認証プロバイダー**: Auth.js EmailProvider
- **セッション管理**: JWT（JSON Web Token）
- **メール送信**: SendGrid / Resend / Amazon SES等
- **セッション有効期限**: 90日間
- **マジックリンク有効期限**: 15分間
